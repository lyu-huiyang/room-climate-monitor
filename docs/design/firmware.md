# room-climate-monitor 固件 — 设计文档

- 日期：2026-11-09
- 范围：ESP32 固件（`firmware/`）

## 1. 背景与目标

每个房间放一块 ESP32-C3 SuperMini，接 SHT40 和 AHT20 两个温湿度传感器，定时把读数上报给服务端（`POST /api/rooms/{room_id}/readings`，见 [server-web.md](server-web.md) 第 4.1 节）。

固件的采样、断网缓存、补传、对时、自愈逻辑来自作者之前的一个私有单房间原型，在真实设备上连续运行了数周。本仓库沿用这些行为，只把上报接口和配置方式改成通用的。

**使用流程**：复制示例配置、填写这块板子的配置，编译烧录，板子就开始上报。不做运行时配网。

## 2. 已定决策

| 项 | 决策 |
|---|---|
| 配置方式 | 编译时配置文件，改完烧录；不做手机配网、网页配置 |
| 硬件 | ESP32-C3 SuperMini + SHT40 + AHT20，所有板子接线相同 |
| 引脚 | 写在代码里，不进配置文件 |
| 404 的处理 | 保留数据、下一分钟重试，板子比房间先上线也不丢数据 |
| 加密连接的证书 | 用开发框架自带的常见根证书集合，不往仓库里放证书文件 |
| 传感器通用化 | 上报格式按名称（`sht40`、`aht20`）组织；配置里可以关掉某个传感器；**不**支持其他型号 |
| 版本固定 | 全部写到具体版本：PlatformIO 平台 `espressif32 @ 7.1.3`，PlatformIO Core `6.2.0`，CI 也用这两个版本 |

## 3. 不做的事

- 运行时配网（AP 模式、蓝牙、网页配置）、OTA 远程升级
- 其他传感器型号、每块板子不同的引脚

**会被视为失败的情况**（即使能编译能上报）：

- 真实配置文件（含 Wi-Fi 密码和设备密钥）进了 git
- 可靠性行为被削弱，例如断网后数据丢失、时钟不准时上报错误的时间戳、卡死后不能自动恢复
- 指示灯会亮（卧室夜里不能有灯光）

## 4. 配置文件

`firmware/include/secrets.example.h` 入库，`firmware/include/secrets.h` 和每个房间的 `secrets.<房间 ID>.h` 被 git 忽略。构建前由 `select_secrets.py` 生成一个只含字面量 `#include` 的头文件，选出本次用的配置：设置了 `RCM_ROOM` 用 `secrets.<RCM_ROOM>.h`，否则用 `secrets.h`，都没有时用示例。用字面量 include 是为了让构建系统跟踪到这个文件：改了配置会重新编译，切换房间不改编译命令行，不会重编整个框架。

| 宏 | 必填 | 说明 |
|---|---|---|
| `WIFI_SSID`、`WIFI_PASS` | 是 | 2.4 GHz Wi-Fi |
| `SERVER_URL` | 是 | 服务端地址，`http://` 或 `https://` 开头，可以带端口，末尾斜杠可有可无，例如 `http://192.168.1.10:8080` |
| `ROOM_ID` | 是 | 服务端注册的房间 ID，格式 `[a-z0-9-]{1,32}`，例如 `living-room` |
| `DEVICE_KEY` | 是 | `rcm room add` 打印的设备密钥 |
| `ENABLE_SHT40`、`ENABLE_AHT20` | 否 | 默认都开；设为 0 时不初始化、不读取这个传感器 |
| `WIFI_TX_POWER` | 否 | 部分 SuperMini 天线匹配差，连不上时降低发射功率 |

上报地址由固件拼成 `SERVER_URL` + `/api/rooms/` + `ROOM_ID` + `/readings`。房间 ID 格式不对、地址不以 `http://` 或 `https://` 开头、地址过长、两个传感器都关掉、Wi-Fi 名称或设备密钥还是示例占位值的配置在编译时报错，而不是烧进去以后才发现不上报。

## 5. 设备行为

- **采样**：每 10 秒一次，对齐到整 10 秒；每次读取已启用的传感器和 Wi-Fi 信号强度。
- **上报**：每分钟一次，在每分钟的第一个采样时刻上报缓存里的读数。单次请求最多 100 条（服务端上限）；缓存多于 100 条时（例如断网恢复后），在同一时刻接着发下一批，直到发完或某一批失败。
- **缓存**：放在开机时不清零的普通内存里（约 17 KB，RTC 内存放不下），靠固定的标识和校验判断内容是否有效。软重启和看门狗重启后保留，断电后清空。容量 1080 条（3 小时），满了覆盖最旧的。每条 16 字节。原型固件的缓存标识不同，刷入本固件后从空缓存开始。
- **对时**：每次开机必须完成一次网络对时（SNTP）才开始采样；Wi-Fi 连上的那一刻如果本次开机还没对时成功，就重启 SNTP。
- **自愈**：Wi-Fi 断开超过 5 分钟就重置 Wi-Fi；30 分钟没有一次成功上报就重启；看门狗 120 秒。
- **指示灯**：常灭。
- **串口日志**：每次采样打印一行，上报结果也打印，方便插 USB 排查。

### 5.1 上报结果的处理

| 服务端返回 | 处理 | 说明 |
|---|---|---|
| 2xx | 从缓存删除这一批 | |
| 400、413 | 丢弃这一批 | 服务端永远不会接受 |
| 401 | 丢弃这一批 | 密钥写在固件里，只有重新烧录才能改，留着没用 |
| 404 | **保留，下一分钟重试** | 房间没注册或 ID 写错；板子比房间先上线时，3 小时内注册好房间就不丢数据 |
| 其他（5xx、网络错误、超时、TLS 失败） | 保留，下一分钟重试 | |

## 6. 通信

- **上报格式**：见 [server-web.md](server-web.md) 第 4.1 节，

  ```json
  {"readings": [{"ts": 1792308900, "sensors": {"sht40": {"t": 24.31, "h": 52.10}, "aht20": {"t": 24.55, "h": 50.80}}, "rssi": -58}]}
  ```

  某个传感器这次没读到，就不写它的键；没有信号强度就不写 `rssi`；一个传感器都没读到的采样不进缓存。
- **请求头**：`X-Device-Key: <DEVICE_KEY>`、`Content-Type: application/json`。
- **明文和加密**：`SERVER_URL` 以 `http://` 开头就用普通连接，以 `https://` 开头就用加密连接并校验服务器证书。证书校验用开发框架自带的常见根证书集合（Let's Encrypt 等公共证书都能通过）：固定版本的平台带的是 Arduino-ESP32 2.0.17，它编译进了 ESP-IDF 的完整根证书集合（约 63 KB），通过 `WiFiClientSecure::setCACertBundle()` 使用。加密握手超时 10 秒（默认 120 秒，和看门狗一样长）。
- **服务端拒绝时**：服务端在返回 401、404、413 之前会读完请求体，固件因此能拿到真实的状态码，而不是把连接被关闭当成网络错误。

## 7. 工程结构

```
firmware/
├── platformio.ini          # env:supermini（设备）、env:native（本机单元测试）
├── select_secrets.py       # 构建前选出本次用的配置文件（第 4 节）
├── include/
│   ├── config.h            # 选择配置文件、默认值、编译期检查
│   ├── secrets.example.h   # 入库
│   └── secrets*.h          # git 忽略
├── lib/core/src/           # 与硬件无关、在本机测试的部分：读数结构、环形缓存、上报内容、策略、地址拼接
├── src/                    # main、传感器、上报（依赖 Arduino 和 Wi-Fi）
├── test/                   # PlatformIO native 单元测试
└── README.md               # 中英文：准备、配置、烧录、看串口日志、排障
```

## 8. 测试与检查

| 部分 | 怎么测 |
|---|---|
| 上报内容组装 | native 单元测试：两个传感器、只有一个、没有信号强度、100 条上限、缓冲区装不下时返回 0；输出的 JSON 由服务端测试交叉验证 |
| 策略 | native 单元测试：第 5.1 节每一行返回码，以及采样对齐、自愈定时、对时判断 |
| 环形缓存 | native 单元测试：校验、边界、满覆盖、跨重启顺序、原型固件的缓存被丢弃 |
| 上报地址拼接 | native 单元测试：有无末尾斜杠、带端口、`http`/`https` 判断 |
| 编译 | `pio run -e supermini`；没有 `secrets.h` 时用示例配置编译（便于 CI） |
| 一键检查 | `scripts/check.sh` 包含固件的 native 测试和编译 |
| 真机验收 | 注册房间、写好配置、烧录：串口日志显示对时成功、每分钟上报成功；网页上出现读数，两路传感器都有曲线；停掉服务端一段时间再恢复，断网期间的数据补传上来，曲线没有缺口 |
